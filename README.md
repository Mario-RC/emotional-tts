# Emotional TTS

This project provides two batch pipelines to build a per-personality voice library and a runtime entry point to synthesize arbitrary text on demand, in English or Spanish, with one of seven emotions per turn.

## Main Scripts

- `voice_design_clone.py`
  Batch pipeline. Generates reference voices from instructions (VoiceDesign) and then clones the final target sentences.

- `voice_clone.py`
  Batch pipeline. Clones directly from uploaded reference audios (without VoiceDesign).

- `voice_runtime.py`
  Runtime entry point for per-turn use cases (e.g. a robot's dialogue loop). Loads the Base clone model once, reuses the VoiceDesign references generated by `voice_design_clone.py` by default, and can also synthesize from a custom reference folder.

- `utils.py`
  Shared audio helpers, including leading/trailing silence trimming used by the batch pipelines and runtime outputs.

- `voice_personality_config.py`
  Central configuration for emotions, reference texts, target sentences, and personality folder name.

## Emotions Used

Emotion keys must match across all configuration dictionaries:

- `anger`
- `disgust`
- `fear`
- `happiness`
- `neutral`
- `sadness`
- `surprise`

## Requirements

- Linux (recommended)
- Python 3.10+
- NVIDIA GPU + CUDA (recommended)
- Access to Hugging Face model downloads

Dependencies are listed in `requirements.txt`.

## Pipeline 1: VoiceDesign + Clone

Script: `voice_design_clone.py`

### What It Does

1. Loads VoiceDesign model: `Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign`.
2. Loads Base model for cloning: `Qwen/Qwen3-TTS-12Hz-1.7B-Base` or `Qwen/Qwen3-TTS-12Hz-0.6B-Base`
3. Reads the per-emotion personality instructions and reference texts.
4. Generates EN and ES references for each emotion.
5. Trims leading/trailing silence from those generated references before saving them.
6. Builds a voice-clone prompt from each cleaned reference.
7. Generates final EN and ES cloned outputs and trims leading/trailing silence before saving.

The reference texts come from `VOICE_DESIGN_REF_TEXT_EN_BY_EMOTION` and
`VOICE_DESIGN_REF_TEXT_ES_BY_EMOTION`. By default, those maps use
`BASE_VOICE_DESIGN_REF_TEXT_EN` and `BASE_VOICE_DESIGN_REF_TEXT_ES` for every
emotion.

The reference silence cleanup happens in `voice_design_clone.py`, not in
`voice_runtime.py`. The runtime only reads the refs that already exist under
`artifacts/<personality>/ref/voice_design_clone_ref/`. You can tune the cleanup
in `ModelConfig` with `trim_ref_silence`, `ref_silence_threshold`, and
`ref_silence_padding_ms`.

The cloned outputs from this batch pipeline are also trimmed before they are
written. Tune that with `trim_clone_silence`, `clone_silence_threshold`, and
`clone_silence_padding_ms`.

### Output For This Pipeline

This script uses one folder per personality:

```text
artifacts/
  <personality_folder>/
    personality.txt
    generated_speech/
      voice_design_clone/
        design_clone_en_<emotion>.wav
        design_clone_es_<emotion>.wav
    ref/
      voice_design_clone_ref/
        voice_design_ref_en_<emotion>.wav
        voice_design_ref_es_<emotion>.wav
```

## Pipeline 2: Clone From Uploaded Audios

Script: `voice_clone.py`

### What It Does

1. Reads reference audios from `artifacts/<personality>/ref/voice_clone_ref/` by default, or from `--ref_dir`.
2. Validates that all expected files exist (14 total).
3. Builds clone prompts by emotion and language.
4. Generates final EN and ES outputs per emotion and trims leading/trailing silence before saving.
5. Copies the reference audios used into the artifacts folder for traceability.
6. Saves metadata in `personality.txt`.

### Important: Reference Transcriptions

In `voice_clone.py`, `VOICE_CLONE_REFS_TEXT_EN_BY_EMOTION` and `VOICE_CLONE_REFS_TEXT_ES_BY_EMOTION`
provide the transcriptions of your reference audios.

You must write these transcriptions in `voice_personality_config.py`:

- `VOICE_CLONE_REFS_TEXT_EN_BY_EMOTION`
- `VOICE_CLONE_REFS_TEXT_ES_BY_EMOTION`

These texts are used by `create_voice_clone_prompt(...)` and should match what is spoken in the uploaded reference audios as closely as possible.
If they do not match, cloning quality can degrade.

By default, these maps use `BASE_VOICE_DESIGN_REF_TEXT_EN` and
`BASE_VOICE_DESIGN_REF_TEXT_ES`. If your uploaded audios say something else,
either update the config or pass the transcript through the CLI.

### Exact Input Audio Names

Upload these files under `artifacts/<personality>/ref/voice_clone_ref/`:

- `voice_clone_ref_en_anger.wav`
- `voice_clone_ref_en_disgust.wav`
- `voice_clone_ref_en_fear.wav`
- `voice_clone_ref_en_happiness.wav`
- `voice_clone_ref_en_neutral.wav`
- `voice_clone_ref_en_sadness.wav`
- `voice_clone_ref_en_surprise.wav`
- `voice_clone_ref_es_anger.wav`
- `voice_clone_ref_es_disgust.wav`
- `voice_clone_ref_es_fear.wav`
- `voice_clone_ref_es_happiness.wav`
- `voice_clone_ref_es_neutral.wav`
- `voice_clone_ref_es_sadness.wav`
- `voice_clone_ref_es_surprise.wav`

If any file is missing, the script raises `FileNotFoundError` with the missing file list.

You can also point the script at another reference folder and pass the shared
reference transcripts from the command line:

```bash
python3 voice_clone.py \
  --ref_dir other_voice_refs \
  --ref_text_en "Exact English transcript spoken in the English reference audios." \
  --ref_text_es "Transcripción exacta en español hablada en los audios de referencia."
```

If all reference audios share the same transcript, use `--ref_text "..."`.

The alternate folder must keep the same file names:

```text
voice_clone_ref_en_<emotion>.wav
voice_clone_ref_es_<emotion>.wav
```

## Runtime: Per-Turn Synthesis

Script: `voice_runtime.py`

### What It Does

1. Loads the Base clone model once. Runtime defaults to `Qwen/Qwen3-TTS-12Hz-0.6B-Base` for lower latency; use `--model-size 1.7B --latency-preset quality` if you prefer the older higher-quality path.
2. Reads on-disk references from `artifacts/<personality>/ref/voice_design_clone_ref/` (default personality: `personality`). Run `voice_design_clone.py` first to produce them.
3. On each request, builds (and caches) a clone prompt for the requested `(language, emotion)` and synthesizes the text into a wav file.
4. Trims leading/trailing silence from the cloned output before writing it.

The first request for a given `(language, emotion)` pays for prompt construction; subsequent requests with the same combo reuse the cached prompt and only run the clone forward pass. For lower first-turn latency, start the runtime server with `--preload-all --warmup`.

Runtime reference filenames are:

```text
artifacts/<personality>/ref/voice_design_clone_ref/voice_design_ref_en_<emotion>.wav
artifacts/<personality>/ref/voice_design_clone_ref/voice_design_ref_es_<emotion>.wav
```

The matching reference transcripts come from
`VOICE_DESIGN_REF_TEXT_EN_BY_EMOTION` and `VOICE_DESIGN_REF_TEXT_ES_BY_EMOTION`.

You can also point runtime at another reference folder:

```bash
python voice_runtime.py \
  --ref_dir other_refs \
  --ref_text_en "Exact English transcript spoken in the English refs." \
  --ref_text_es "Transcripción exacta en español hablada en las refs." \
  --text "Hola" \
  --language Spanish \
  --emotion happiness
```

If all references share the same transcript, use `--ref_text "..."`.

When using `--ref_dir`, the transcript passed through `--ref_text`,
`--ref_text_en`, or `--ref_text_es` should match what is spoken in those custom
reference audios.

Custom runtime reference folders may use either naming style:

```text
voice_design_ref_en_<emotion>.wav
voice_design_ref_es_<emotion>.wav
voice_clone_ref_en_<emotion>.wav
voice_clone_ref_es_<emotion>.wav
```

### Inputs

- `text` — what to say for a single output.
- `texts` — server JSON only; list of up to 3 short phrases generated in one batch with the same language. `emotion` can be shared or one emotion per phrase.
- `emotion` — a single emotion for all phrases, or in server batch JSON a list with one emotion per phrase.
- `language` — `English` | `Spanish` (also accepts `en` / `es`).
- Emotion values — one of `anger`, `disgust`, `fear`, `happiness`, `neutral`, `sadness`, `surprise`.
- `--output` — optional destination folder/path. Relative paths are saved under `artifacts/<personality>/generated_speech/voice_runtime/` using fixed runtime names: `voice_runtime_1.wav`, `voice_runtime_2.wav`, `voice_runtime_3.wav`, and `voice_runtime.wav` for the concatenated batch file. These files are created at startup if they do not exist yet, then overwritten in place by each request.
- `--ref_dir` — optional folder containing reference audios.
- `--ref_text`, `--ref_text_en`, `--ref_text_es` — optional shared reference transcript overrides.
- `--model-size` — `0.6B` or `1.7B`; default is `0.6B` for runtime speed.
- `--clone-model-id` — full model id or local model path; overrides `--model-size`.
- `--latency-preset` — `fast`, `balanced`, or `quality`; default is `fast`.
- `--prompt-mode` — `icl` keeps reference speech codes for stronger emotion/style cloning; `x_vector` is faster but less expressive.
- `--max-new-tokens`, `--do-sample`, `--top-k`, `--top-p`, `--temperature` — optional generation tuning overrides.
- `--subtalker-dosample`, `--subtalker-top-k`, `--subtalker-top-p`, `--subtalker-temperature` — optional Qwen3-TTS subtalker generation overrides.
- `--non-streaming-mode` / `--no-non-streaming-mode` — forwarded to `generate_voice_clone`; keep it disabled for normal runtime because enabling it can make Qwen3-TTS generate long silent regions.
- `--preload-all` — builds and caches all English/Spanish emotion prompts before accepting requests.
- `--preload language:emotion` — builds and caches selected prompts, e.g. `--preload Spanish:happiness --preload English:fear`.
- `--warmup` — runs one short generation and discards it so the model/CUDA path is already initialized.
- `--warmup_language`, `--warmup_emotion`, `--warmup_text` — optional warmup controls.

### Modes

One-shot (loads model, synthesizes one sentence, exits):

```bash
python voice_runtime.py --text "¡Hola, qué alegría verte!" --language Spanish --emotion happiness
```

This writes:

```text
artifacts/personality/generated_speech/voice_runtime/voice_runtime_1.wav
```

Hot server (model stays loaded; one JSON request per stdin line, one JSON reply per stdout line):

```bash
python voice_runtime.py --serve
{"text":"Hola","language":"Spanish","emotion":"happiness"}
{"text":"Wait, did you hear that?","language":"English","emotion":"fear"}
{"texts":["Wait.","Did you hear that?","I think something moved."],"language":"English","emotion":"fear"}
{"texts":["Congratulations! That's wonderful news!","I'm so happy for you, but I must admit, wedding planning sounds terrifying.","Have you set a date yet?"],"language":"English","emotion":["happiness","fear","neutral"]}
```

Recommended server for the mixed-emotion chatbot example:

```bash
python voice_runtime.py --serve --model-size 0.6B --latency-preset fast --prompt-mode icl --preload-all --warmup --warmup_language English --warmup_emotion neutral --warmup_text "Hello."
```

Use `--preload-all` when you want every English/Spanish emotion prompt cached
before the server accepts requests. `--warmup` only runs one short generation;
that is usually enough to initialize the model/CUDA path, while the preloaded
prompts cover the other language/emotion combinations.

After the server prints `{"ready": true, ...}`, paste one JSON request per line:

```json
{"texts":["Congratulations! That's wonderful news!","I'm so happy for you, but I must admit, wedding planning sounds terrifying.","Have you set a date yet?"],"language":"English","emotion":["happiness","fear","neutral"]}
```

At startup, the runtime prints the effective configuration to `stderr`: model id, latency preset, prompt mode, generation options, reference folder, output folder, preload, and warmup settings. The first `stdout` JSON only reports that the server is ready and how long startup took:

```json
{"ready": true, "startup_seconds": 12.345}
```

Each successful reply includes the generated wav name and request latency:

```json
{"ok": true, "output": "voice_runtime_1.wav", "elapsed_seconds": 1.234, "effective_max_new_tokens": 384, "trim_removed_start_seconds": 0.596, "trim_removed_end_seconds": 0.465}
```

For batch requests with `texts`, the same loaded model and cached prompt are
used for all phrases. `emotion` can be one shared emotion or a list aligned
with `texts`:

```json
{"ok": true, "outputs": ["voice_runtime_1.wav", "voice_runtime_2.wav", "voice_runtime_3.wav"], "elapsed_seconds": 2.345, "effective_max_new_tokens": 384, "batch_size": 3}
```

Batch replies also include `combined_output`, a single wav made by concatenating
the generated phrase wavs in order with 250 ms of silence between phrases.

With per-phrase emotions, the output slots stay generic and the response keeps
the per-item emotion metadata:

```json
{"ok": true, "outputs": ["voice_runtime_1.wav", "voice_runtime_2.wav", "voice_runtime_3.wav"], "combined_output": "voice_runtime.wav", "elapsed_seconds": 2.345, "effective_max_new_tokens": 384, "batch_size": 3}
```

For chatbot-style output, prefer `texts` instead of concatenating several short
sentences into one long `text`. The batch path keeps the same model and prompt
loaded, avoids long near-silent generations, and returns one wav per phrase.

Low-latency server for dialogue loops:

```bash
python voice_runtime.py --serve --preload-all --warmup
```

This uses the runtime defaults: `--model-size 0.6B --latency-preset fast --prompt-mode icl`. Startup is slower, but the first real turn is faster because prompts are cached and the generation path is warm before the server prints `{"ready": true}`.

The `fast` preset uses compact sampling (`top_k=5`, `top_p=0.8`) and caps `max_new_tokens` at `384`. This avoids the near-silent outputs seen with fully deterministic generation while keeping latency low. If a request contains longer text and the configured token cap is too low, runtime raises the effective `max_new_tokens` for that request to avoid truncated speech. The `balanced` preset keeps a wider sampling space. The `quality` preset leaves Qwen3-TTS generation defaults unchanged.

Fast reliable mode for longer turns or mixed-emotion chatbot replies:

```bash
python voice_runtime.py --serve --model-size 0.6B --latency-preset fast --prompt-mode icl --preload-all --warmup --warmup_language English --warmup_emotion neutral --warmup_text "Hello."
```

`--prompt-mode x_vector` can be faster, but with some references it can produce very low-amplitude or silent audio. Use `icl` for reliable audible output.

Higher quality, slower:

```bash
python voice_runtime.py --serve --model-size 1.7B --latency-preset quality --preload-all --warmup
```

If you only need a few emotions at first:

```bash
python voice_runtime.py --serve --preload Spanish:happiness --preload Spanish:neutral --warmup
```

In-process (recommended when the dialogue loop is Python):

```python
from voice_runtime import EmotionalSpeaker

speaker = EmotionalSpeaker(personality="personality")
speaker.preload("Spanish", "happiness")  # optional, removes first-turn latency
speaker.warmup("Spanish", "happiness")  # optional, warms one short generation
speaker.say(text="Hola", language="Spanish", emotion="happiness")  # auto path
speaker.say(text="Hola", language="Spanish", emotion="happiness", output="t1.wav")
```

With custom references in Python:

```python
from pathlib import Path
from voice_runtime import EmotionalSpeaker

speaker = EmotionalSpeaker(
    personality="personality",
    ref_dir=Path("other_refs"),
    ref_text_es="Transcripción exacta hablada en los audios españoles.",
)
speaker.say(text="Hola", language="Spanish", emotion="happiness")
```

Switch personalities with `--personality other_personality` (CLI) or `EmotionalSpeaker(personality="...")` (Python).

## Configuration

Edit `voice_personality_config.py` to change:

- `DEFAULT_PERSONALITY_FOLDER`
- `BASE_IDENTITY_EN`
- `BASE_IDENTITY_ES`
- `BASE_VOICE_DESIGN_REF_TEXT_EN`
- `BASE_VOICE_DESIGN_REF_TEXT_ES`
- `PERSONALITY_TRAITS_BY_EMOTION`
- `VOICE_DESIGN_REF_TEXT_EN_BY_EMOTION`
- `VOICE_DESIGN_REF_TEXT_ES_BY_EMOTION`
- `VOICE_CLONE_REFS_TEXT_EN_BY_EMOTION`
- `VOICE_CLONE_REFS_TEXT_ES_BY_EMOTION`
- `DEFAULT_SENTENCES_EN_BY_EMOTION`
- `DEFAULT_SENTENCES_ES_BY_EMOTION`
- `DEFAULT_EMOTION_ORDER`

`voice_clone.py` and `voice_design_clone.py` use this configuration by default.

For `voice_design_clone.py`, use `VOICE_DESIGN_REF_TEXT_EN_BY_EMOTION` and `VOICE_DESIGN_REF_TEXT_ES_BY_EMOTION` to define per-emotion ref transcripts.

For `voice_clone.py`, use `VOICE_CLONE_REFS_TEXT_EN_BY_EMOTION` and `VOICE_CLONE_REFS_TEXT_ES_BY_EMOTION` to define per-emotion ref transcripts of uploaded audios. You can also override the shared transcript from the CLI with `--ref_text`, `--ref_text_en`, or `--ref_text_es`.

## Execution

From the `emotional-tts/` folder:

```bash
python voice_design_clone.py
python voice_clone.py
```

To override the personality folder name used by `voice_design_clone.py` or `voice_clone.py`:

```bash
python3 voice_design_clone.py --output_dir personality
python3 voice_clone.py --output_dir personality
```

The script also accepts a legacy freeform style:

```bash
python3 voice_design_clone.py -- output_dir personality 1
python3 voice_clone.py -- output_dir personality 1
```

Both commands save into `artifacts/personality/`.

Their generated outputs do not overwrite each other because they use different
file names:

```text
artifacts/personality/generated_speech/voice_design_clone/design_clone_en_<emotion>.wav
artifacts/personality/generated_speech/voice_design_clone/design_clone_es_<emotion>.wav
artifacts/personality/generated_speech/voice_clone/clone_en_<emotion>.wav
artifacts/personality/generated_speech/voice_clone/clone_es_<emotion>.wav
artifacts/personality/generated_speech/voice_runtime/voice_runtime_1.wav
artifacts/personality/generated_speech/voice_runtime/voice_runtime_2.wav
artifacts/personality/generated_speech/voice_runtime/voice_runtime_3.wav
artifacts/personality/generated_speech/voice_runtime/voice_runtime.wav
```

To synthesize one runtime utterance from the default VoiceDesign references:

```bash
python3 voice_runtime.py \
  --text "¡Hola, qué alegría verte!" \
  --language Spanish \
  --emotion happiness
```

To synthesize one runtime utterance from a custom reference folder:

```bash
python3 voice_runtime.py \

  --ref_text_es "Transcripción exacta hablada en los audios españoles." \
  --text "¡Hola, qué alegría verte!" \
  --language Spanish \
```

## Common Issues

1. CUDA out-of-memory error
  Reduce GPU load or free GPU processes.

2. FlashAttention error
  Install a compatible `flash-attn` version or set `attn_implementation = "eager"`.

3. Emotion mapping validation error
  Ensure emotion keys are identical across all dictionaries.

4. Audio read/write error
  Check `soundfile` installation and required system audio libraries.
